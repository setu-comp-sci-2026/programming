## Exercise 4 — Game Character

Create `ex4_character.py`. Write a `GameCharacter` class with:

- a read-only `name` property (raise `ValueError` in `__init__` if the name is blank);
- a `health` property, from 0 to 100, starting at 100. This setter does **not** raise an error. It **clamps** the value instead: anything above 100 becomes 100, and anything below 0 becomes 0;
- a read-only computed property `is_alive`, which is `True` while health is above 0;
- `take_damage(amount)` and `heal(amount)`. Both raise `ValueError` if `amount` is not positive, and both change health **through the setter** so that clamping happens in one place;
- `heal()` raises `ValueError` if the character has already been defeated;
- `__str__` showing a ten-block health bar, e.g. `Aoife [######----] 65/100`. (Hint: `health // 10` gives the number of `#` blocks.)

```python
hero = GameCharacter("Aoife")
print(hero)                 # Aoife [##########] 100/100
hero.take_damage(35)
print(hero)                 # Aoife [######----] 65/100
hero.heal(500)
print(hero)                 # Aoife [##########] 100/100  (clamped)
hero.take_damage(250)
print(hero, hero.is_alive)  # Aoife [----------] 0/100 False

try:
    hero.heal(10)           # should raise ValueError
except ValueError as e:
    print(f"Error: {e}")

try:
    hero.name = "Bob"       # read-only, should raise AttributeError
except AttributeError:
    print("Error: name is read-only")
```

**Think:** The `health` setter clamps, but `Person.age` in Section 06 raises an error. When is clamping the better choice, and when is raising better?

## Exercise 5 — User Account with a Password

Create `ex5_user.py`. Some data should never be readable from outside the object, and a password is the obvious example. Write a `UserAccount` class with:

- `__init__(self, username, password)`. Store the username in lower case and make it available through a **read-only** `username` property;
- a password stored in `_password` with **no getter and no property**. Outside code can never read it;
- password rules: at least 8 characters and at least one digit. Put these checks in a **private helper method** `_check_password_rules(password)`, which raises `ValueError`. Call it from `__init__` and from `change_password()`, so the rules are written only once;
- `check_password(attempt)`, which returns `True` or `False`. After **3 wrong attempts in a row** the account is locked. A correct attempt resets the count to 0;
- a read-only property `is_locked`. Calling `check_password()` on a locked account raises `ValueError`;
- `change_password(old, new)`. The old password must be correct, and the new one must follow the rules;
- `__str__`, e.g. `User 'niamh' (active)` or `User 'niamh' (LOCKED)`. Never include the password!

```python
u = UserAccount("Niamh", "secret123")
print(u)                                # User 'niamh' (active)
print(u.check_password("secret123"))    # True

for attempt in ["guess1", "guess2", "guess3"]:
    print(u.check_password(attempt))    # False, False, False
print(u)                                # User 'niamh' (LOCKED)

try:
    u.check_password("secret123")       # locked, so ValueError
except ValueError as e:
    print(f"Error: {e}")

for bad in ["short1", "longpassword"]:
    try:
        UserAccount("test", bad)
    except ValueError as e:
        print(f"Rejected: {e}")
```

**Think:** Why does the class have no `get_password()` method? What should the rest of the program do instead when it needs to know whether a password is right?

## Exercise 6 — Library Book Class

Create a `Book` class representing a library book:
- Properties: `title`, `author`, `isbn` (read-only), `is_available`
- Methods: `check_out(borrower_name)` — marks as unavailable, records borrower
- `return_book()` — marks as available, clears borrower
- `__str__` — shows title, author, and availability status

```python
book = Book("Python Crash Course", "Eric Matthes", "978-1718502703")
print(book)                   # shows as available
book.check_out("Alice")
print(book)                   # shows as checked out by Alice
book.return_book()
print(book)                   # shows as available again

# Try checking out a book that's already out
book.check_out("Bob")
try:
    book.check_out("Carol")   # should raise an error
except Exception as e:
    print(f"Error: {e}")
```
