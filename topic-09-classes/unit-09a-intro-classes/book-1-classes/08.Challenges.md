## Challenge 1 — Transfer between accounts

Start from your validated `BankAccount` (with transaction history) from Section 04. Add a method:

```python
def transfer(self, other, amount):
```

It should withdraw `amount` from `self` and deposit it into `other`, which is **another `BankAccount` object**. If the withdrawal fails, `other` must **not** receive any money.

Test with:

```python
alice = BankAccount("ACC001", "Alice", 500)
bob = BankAccount("ACC002", "Bob", 100)
alice.transfer(bob, 200)
print(alice)   # €300.00
print(bob)     # €300.00

try:
    bob.transfer(alice, 1000)
except ValueError as e:
    print("Transfer failed:", e)
print(alice)   # still €300.00
print(bob)     # still €300.00
```

**Think:** Why must the withdrawal happen **before** the deposit?

## Challenge 3 — Find the bugs

A student wrote this class. It has **four** faults. Some raise an exception; others give the wrong answer. Find and fix each one, and say which kind of fault it is.

```python
class Thermostat:
    def __init__(self, room, target):
        self.room = room
        target = target
        self.current = 18

    def heat_up(self, degrees):
        self.current = degrees

    def needs_heating():
        return self.current < self.target

    def __str__(self):
        print(f"{self.room}: {self.current}°C (target {self.target}°C)")


t = Thermostat("Kitchen", 21)
print(t.needs_heating())
t.heat_up(2)
print(t)
```

**Hint:** Fix them one at a time. Run after each fix and read the new traceback.

## Challenge 4 — A Dog Day Care class

Use your `Dog` class from the exercises, and create a second class, `DogDayCare`:

- `__init__(self, name, capacity)` stores the name, the capacity and an **empty list** `self.dogs`.
- `check_in(dog)` adds a `Dog` object to the list. Raise `ValueError` if the day care is full, or if a dog with the same name is already checked in.
- `check_out(name)` removes the dog with that name. Raise `ValueError` if no such dog is found.
- `average_age()` returns the average age of the dogs, or `0` if empty.
- `__str__` returns a summary, e.g. `Happy Paws: 2/3 dogs`.

Test with a capacity of 3: check in three dogs, try a fourth (should fail), check one out, then check the fourth in successfully.

**Think:** This is an object that **contains a list of other objects**. Where else could you use this pattern? (We will do much more of this in the next topic.)
