# 3. One Bank manages many accounts

We now need a class to manage a **collection** of `BankAccount` objects.

Add this class **after** `BankAccount` and **before** your test code:

~~~python
class Bank:
    def __init__(self):
        self.accounts = []
~~~

In your test code, create a bank and add the account objects you already created:

~~~python
bank = Bank()
bank.accounts.append(alice)
bank.accounts.append(bob)
bank.accounts.append(charlie)

print(len(bank.accounts))
print(bank.accounts[0])
~~~

## Think about it

- What does `self.accounts` contain: strings, dictionaries or objects?
- Why is `BankAccount` responsible for deposits while `Bank` manages the list?
- Predict the result of the following, **then run it**:

~~~python
alice.balance = alice.balance + 25
print(bank.accounts[0].balance)
~~~

> Both `alice` and `bank.accounts[0]` refer to the **same object**. The list did not create a copy.
