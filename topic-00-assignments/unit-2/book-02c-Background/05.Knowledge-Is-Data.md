# 5. Important Principles – Knowledge is Data and  Changing Knowledge Without Changing Python

## Knowledge is Data

One of the most important ideas in this assignment is:

> **The expert knowledge should be separated from the Python code that processes it.**

Consider the following program:

```python
if answer1 == "yes" and answer2 == "no":
    print("Recommendation A")
elif answer1 == "no" and answer3 == "yes":
    print("Recommendation B")
elif answer2 == "yes" and answer4 == "no":
    print("Recommendation C")
```

This may make decisions, but the expert knowledge is **hard-coded into the program**.

Your final expert system should take a different approach:

```text
KNOWLEDGE BASE
      |
      | Questions
      | Rules
      | Recommendations
      ↓
INFERENCE ENGINE
      |
      | applies the rules
      ↓
USER ANSWERS
      |
      ↓
RECOMMENDATION
```

The Python program should contain the logic for **processing rules**.

The Knowledge Base should contain the actual **expert knowledge**.

## Changing Knowledge Without Changing Python

A major goal of your final system is that its knowledge can be changed without having to rewrite the decision-making Python code.

For example, suppose your system contains:

```text
RULE 12

IF:
    power = no
    lights = yes
    fan = no

THEN:
    Recommend R2
```

You should be able to change this rule in the Knowledge Base without adding another large `if/elif` statement to your inference engine.

Similarly, it should be possible to add suitable new:

- questions
- recommendations
- rules

without redesigning the entire Python application.

This separation between **knowledge** and **program logic** is a key requirement of the project.
