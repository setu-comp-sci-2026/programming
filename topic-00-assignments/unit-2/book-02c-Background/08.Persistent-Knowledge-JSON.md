# 8. Persistent Knowledge – JSON, Saving and Loading to/from files

## JSON

Eventually, your Knowledge Base should be stored outside your Python program.

JSON is recommended.

For example:

```json
{
    "questions": [
        {
            "id": "Q1",
            "text": "Does the computer power on?",
            "type": "yes_no",
            "category": "power"
        },
        {
            "id": "Q2",
            "text": "Are any power lights visible?",
            "type": "yes_no",
            "category": "power"
        }
    ],
    "recommendations": [
        {
            "id": "R1",
            "title": "Possible Power Supply Problem",
            "description": "Check the computer's power supply."
        }
    ],
    "rules": [
        {
            "id": "RULE1",
            "conditions": {
                "Q1": "no",
                "Q2": "yes"
            },
            "recommendation": "R1"
        }
    ]
}
```

When the program starts, it should load its expert knowledge from the Knowledge Base.


## Saving and Loading to/from files

Changes made to the Knowledge Base must persist after the program closes.

For example, if an administrator:

1. adds a new recommendation
2. saves the Knowledge Base
3. exits the program
4. starts the program again

the new recommendation should still exist.

Your program should therefore be capable of:

```text
JSON File
    ↓
Load
    ↓
Python Program
    ↓
Modify Knowledge
    ↓
Save
    ↓
JSON File
```
