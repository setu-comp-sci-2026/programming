# Running Python: Terminal vs VS Code Run

**Working directories · relative paths · file locations · pathlib**

When you run a Python program, it needs a **starting folder** for finding files such as journal.txt or knowledge.json. This is called the **current working directory (CWD)**.

> **Important:** The working directory is not necessarily the folder containing your .py file.


## 1. Set up a project

Create this folder structure:

```text
PythonLabs/
    main.py
    journal.txt
```

Put this text into `journal.txt`:

```text
Today I learned about file paths.
```

Add the following code to `main.py`:

```python
import os
from pathlib import Path

print("Working directory:", os.getcwd())
print("Python script folder:", Path(__file__).resolve().parent)

with open("journal.txt", "r", encoding="utf-8") as file:
    print(file.read())
```

The two paths printed by this program **might be different**.

## 2. Method A — Run from the terminal

Open the VS Code terminal (**Terminal → New Terminal**). Navigate to your project folder. For example, in PowerShell:

```powershell
cd "C:\Users\Student\Documents\PythonLabs"
```

Check where you are:

```powershell
pwd
```

Then run the program:

```powershell
python main.py
```

On some computers you may use **py main.py** instead.

Because you started Python from `PythonLabs`, its working directory is normally `PythonLabs`. The relative path `journal.txt` points to the file in that folder.

## 3. Method B — Press Run in VS Code

Open `main.py` in VS Code and select **Run Python File** (the play button).

VS Code launches Python for you. The working directory depends on the **run command, extension and configuration**. The Python extension's **Run Python File** command commonly runs from the script's folder, but other methods, including debugging configurations or Code Runner, may behave differently.

**Compare the two paths printed by your program.** Are they the same?

| How you run the program | What determines the working directory? |
|---|---|
| cd to a folder, then python main.py | The folder you navigated to in the terminal |
| VS Code **Run Python File** | The Python extension's run behaviour and settings |
| VS Code debugger | The debug configuration (for example, its cwd setting) |

> Pressing Run does **not** automatically guarantee that Python will look beside your script for every file.

## 4. What if you run the script from another folder?

Suppose your terminal is in Documents, one folder **above** PythonLabs:

```powershell
cd "C:\Users\Student\Documents"
python PythonLabs\main.py
```

The script still runs, but the working directory is now Documents.

This statement:

```python
open("journal.txt", "r", encoding="utf-8")
```

looks for `Documents/journal.txt`, **not** `Documents/PythonLabs/journal.txt`. If that file is absent, Python raises `FileNotFoundError`.

## 5. A more reliable approach: `pathlib`

If you want to read a file stored **beside your Python script**, build its path from the script's location:

```python
from pathlib import Path

folder = Path(__file__).resolve().parent
file_path = folder / "journal.txt"

with open(file_path, "r", encoding="utf-8") as file:
    print(file.read())
```

- `__file__` refers to the Python script's file path when running a `.py` file.
- `.resolve()` gives its absolute path.
- `.parent` gives the folder containing the script.
- `/ "journal.txt"` adds the filename to that folder path.

Now the program can find `journal.txt` beside `main.py` even when you launch it from a different working directory.

**Note:** `__file__` is intended here for a saved `.py` script; it may not be available in an interactive Python session.

## 6. Apply this to the PC Troubleshooter

Imagine this project:

```text
PC_Troubleshooter/
    main.py
    knowledge.json
```

To load the knowledge base:

```python
import json
from pathlib import Path

folder = Path(__file__).resolve().parent
knowledge_path = folder / "knowledge.json"

with open(knowledge_path, "r", encoding="utf-8") as file:
    knowledge = json.load(file)

print(knowledge)
```

This is particularly useful when sharing the project with someone else: the program doesn't depend on a hard-coded path such as `C:/Users/Student/...`.
