# 9. Changing Knowledge Without Changing Python

A major goal of your final system is that its knowledge can be changed without having to rewrite the decision-making Python code.

For example, suppose your system contains:

```text
RULE 12

IF:
    power = no
    lights = yes
    fan = no

THEN:
    Recommend R2
```

You should be able to change this rule in the Knowledge Base without adding another large `if/elif` statement to your inference engine.

Similarly, it should be possible to add suitable new:

- questions
- recommendations
- rules

without redesigning the entire Python application.

This separation between **knowledge** and **program logic** is a key requirement of the project.
